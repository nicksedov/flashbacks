### Responsive

- **Mobile lightbox panel (`mobile-lightbox-adaptation`, 2026-10-13):** below the `md` breakpoint every lightbox presents the image as full-area content and the detail panel as a collapsible overlay that never resizes the image. The overlay is a bottom sheet in portrait and a right sheet in landscape, drawn over the image with a `bg-background/60` scrim that dismisses the panel on tap. Its toggle is a labelled disclosure carrying `aria-expanded`/`aria-controls`, focus management (focus into the panel on expand, back to the toggle on collapse), and a 44×44 touch target, and it is deliberately exempt from the icon-first collapse because it is the only affordance for the hidden panel. The panel keeps a focused input above the on-screen keyboard with a `dvh` height (paired with `interactive-widget=resizes-content`), clears the device safe areas with `env(safe-area-inset-*)` padding, suppresses its transition under `prefers-reduced-motion` via `motion-safe:`, and collapses on Escape/back before the dialog closes. The lightbox chrome (mode tab-bar wrapping, icon-first action labels, 44×44 chrome/close targets, long informational readouts collapsing to the info icon, and the truncating trash title) applies the existing mobile rules. See [`openspec/specs/design-system/spec.md`](../openspec/specs/design-system/spec.md).
- **Lightbox mobile rules must stay below `md` (`mobile-lightbox-adaptation`, 2026-10-13):** the lightbox's mobile-only utilities carry an explicit `max-md:` scope — `max-md:landscape:` for the orientation sheet and `max-md:flex-wrap` for the mode tab bar. Tailwind emits the orientation media block *after* the `md` block, so at equal specificity a bare `landscape:w-[80%]`/`landscape:h-auto` beats `md:w-[400px]`/`md:h-full` on every landscape desktop viewport and squeezes the image area to roughly 20 %; scoping the variant removes the conflict regardless of emission order. Each lightbox also exposes exactly **one** close control: [`LightboxDialog.tsx`](../webapp/src/components/gallery/lightbox/LightboxDialog.tsx) keeps its own circle close (44×44 below `md`, the 32px `h-8 w-8` style at `md`+, stacked above the panel) and suppresses the shared one with the additive `hideClose` opt-out on [`dialog.tsx`](../webapp/src/components/ui/dialog.tsx)'s `DialogContent` — which every other dialog, including the trash lightbox, still uses. The collapsed informational readout's popup is left-anchored and width-clamped so it opens inside the lightbox instead of overflowing the lightbox's left edge.
